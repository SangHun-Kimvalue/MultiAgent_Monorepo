# ACP Lessons Learned

## LESSON-009 — 관제 도구가 관제 대상을 느리게 만들면 그것도 관측 결함이다 (2026-07-28)

**현상**: 트랙을 닫은 직후 UI를 띄우자 두 결함이 바로 드러났다.
① "최근 알림"이 전부 `UNKNOWN`/`-` — 알림이 없어서가 아니라 **읽는 위치가 달랐다**.
저장 행은 표시 필드를 `payload` 안에 두는데 화면은 최상위에서 읽었다. `created_at`만
최상위라 **시각만 정상**이었다. SSE 경로는 폴러가 평평하게 발행해 정상이었으므로,
**두 경로가 다른 모양**이었고 초기 로드만 깨져 있었다.
② 폴링 틱이 **15초마다 3.7~4.7초** 걸리는데 전부 동기 호출이라 **이벤트 루프를 25~30%
막았다**. 브라우저에서 14ms짜리 API가 334ms 걸린 이유가 그 대기였다.

**가설을 측정으로 기각한 기록**: 원인을 "행마다 커밋(fsync)"으로 보고 배치 트랜잭션을
설계했다. 실측하니 배치는 **효과가 없었고**(640ms vs 728ms), 진짜 원인은
`PRAGMA synchronous=FULL`이었다(FULL 682ms vs NORMAL 17ms / 360행 — **40배**).
측정하지 않았으면 **효과 없는 리팩터링을 하고 "고쳤다"고 보고**했을 것이다.

**규칙**:
1. **같은 사실을 두 경로로 내보내면 모양을 한 곳에서 정의한다.** 한쪽만 고치면 다른 쪽이
   조용히 깨지고, 그 경로를 덜 보기 때문에 오래 산다.
2. 투영은 **행의 사실을 덮어쓰지 않는다**(`session_id`·`created_at`·`payload` 원본).
   누가 말한 사실인지가 다르다.
3. 성능 수정은 **원인을 측정으로 특정한 뒤에** 한다. 그럴듯한 가설(배치)이 틀릴 수 있다.
4. `PRAGMA synchronous`는 **테이블이 아니라 연결 단위**다. 내구성을 낮출 거면 그 대가가
   허용되는 데이터만 **전용 연결**로 분리하라 — 이 저장소의 세션 행은 매 틱 재유도되지만
   **승인 감사는 재유도되지 않는다**.
5. 동기 I/O를 이벤트 루프에서 돌리지 않는다. 스레드로 뺄 때는 **연결 소유권**을 단계별로
   못박는다(`check_same_thread=False`는 허용일 뿐 직렬화가 아니다).
6. 발행은 **DB 반영 뒤**에 한다. 섞으면 "화면엔 있는데 DB엔 없는" 구간이 생긴다.
7. **반영하지 못한 틱을 성공으로 고지하지 않는다.** 전용 연결을 도입하면 `busy_timeout`
   초과 같은 새 실패 경로가 생기는데, 수집기가 선언한 `success_complete`를 그대로 두면
   세션이 반영되지 않은 틱이 정상 관측으로 읽힌다(구현리뷰가 잡은 회귀).

**검증**: pytest 516 passed/1 skipped(+16) · ruff · mypy strict 29 · node JS 계약 3종.
mutation 12건 실측. 라이브(실 DB 사본 3회): `_tick` **4737ms → 920~1099ms**,
**루프 최대 차단 4700ms → 16~32ms**. 브라우저: 알림이 `holding / 세션 홀딩 감지 / detail`로
정상 렌더.
독립 설계검토 2R APPROVED · 독립 구현리뷰 **1R**(P1 1 · P2 2 · P3 1 전부 반영).
**자기 점검으로 잡은 것 둘**: V6(루프 비차단) 검사가 처음에 판별력이 없었다 — 차단이 끝난 뒤
heartbeat가 `stop`을 먼저 보고 빠져나가 큰 간격이 기록되지 않았다. P3 게이트도 그 케이스를
넣지 않아 mutation을 못 잡았다. 둘 다 mutation으로 발견해 고쳤다.
**NOT CLAIMED**: 정전 시나리오 실측 · codex 3.8GB 소스의 장기 성능 · 브라우저 e2e 자동화.

## LESSON-008 — 이름이 행동을 함의하면 **그 행동이 실제로 가능해야** 한다 (2026-07-28)

**현상**: 화면이 853건을 "정리 대상"이라 불렀다. 그런데 대시보드에 정리 기능이 없고,
CLI `purge --app`은 앱 전체 삭제인 데다 **원본 파일이 남아 있으면 다음 수집에서 같은 행이
재생성**된다(수집기는 시간 컷오프 없이 전량 재스캔). `stale_ttl=60분`이라 오늘 아침에 끝낸
세션 123건까지 그 이름에 들어갔다. LESSON-005가 "하지 않은 일을 고지하기"였다면 이것은
그 사촌 — **할 수 없는 일을 시키기**다.

**규칙**:
1. 이름이 행동을 함의하면 그 행동을 **실제로 제공하거나**, 이름을 **사실**로 바꿔라.
   `cleanup_required` → `inactive_total`, "정리 대상" → "비활성".
2. 고칠 때 **또 다른 과장을 넣지 마라.** `ended_*`("종료됨")로 갈 뻔했는데, 이 판정이
   증명하는 것은 "임계 시간 동안 활동 없음 + 실행 신호 관측"까지이고 세션은 `--resume`으로
   이어갈 수 있다. 종료 이벤트를 본 적이 없다.
3. 정상 상태를 **영구 경고로 표시하지 마라.** 활동이 멈춘 세션이 쌓이는 것은 사실이지
   이상이 아니다. 등급에서 빼되 **숫자는 계속 보여준다**(숨기는 것과 다르다).
4. 공개 이름을 바꿀 때 **옛 이름은 같은 계산의 투영으로 남긴다**(저장소 grep은 저장소 밖
   소비자가 없음을 증명하지 못한다).
5. 지속되지 않는 조치는 **그 사실을 말한다** — `purge`는 지운 행이 재생성된다고 고지한다.

**대상을 고를 때**: prune/`missing`을 하려다 **원본이 사라진 행이 0건**임을 실측하고
접었다. 메커니즘이 실재해도 **데이터가 없으면 검증할 수 없는 기능**이 된다.

**공정에 대한 교훈(이 트랙 전체)**: 대상 선정은 실측 기반이라 합리적이었지만 **공정 무게가
과했다**. 슬라이스당 1300~1700줄, 리뷰 5~10라운드였고, 후반 라운드는 슬라이스 주제를 벗어난
일반 강건성으로 흘렀다(실행 증거 표시 슬라이스에서 `NaN`/`Infinity` 처리). "P1 0건까지
무한 루프" 규칙이 비용을 폭증시켰다. 이 슬라이스는 **이름 변경**이라 리뷰 1라운드 · 테스트
4개 · mutation 3건으로 끝냈다 — **공정 무게는 대상 크기에 맞춘다.**

**검증**: pytest 500 passed/1 skipped(+4) · ruff · mypy strict 28 · node JS 계약 3종.
mutation 3건 실측(옛 필드 삭제 · 경고 등급 부활 · purge 고지 제거). 도달 가능성 검사는
게이트가 아니라 회귀 검사임을 명시했다(구현리뷰 P2 수용).
독립 설계검토 3R APPROVED · 독립 구현리뷰 **1R APPROVED**(의도적으로 1라운드).
**NOT CLAIMED**: 브라우저 확인(라벨 변경이라 서버·store 계약으로 충분하다고 판단) ·
리뷰어 측 기계 검증(read-only 샌드박스 — 이 트랙 전 슬라이스 공통).

## LESSON-007 — 한 배열이 **어휘·순서·후보**를 겸하면, 어긋나는 순간 사실이 증발한다 (2026-07-28)

**현상**: 대시보드의 `ACP_STATES` 하나가 상태 어휘 · 표시 순서 · 필터 후보 · URL 화이트리스트를
전부 겸했다. 서버 응답에 그 배열 밖 상태가 실린 상황을 그대로 주입해 실측하니:

```
배지 합 1  vs  전체 101      ← 100건이 고지 없이 사라짐
availableStates: ["live"]    ← 필터 후보에 없어 도달 불가
healthLabel: "정상"          ← 미지 상태 100건을 보고도 정상 단언
```

**왜 겸직이 결함인가**: 축이 다른 사실이 한 값에 묶이면 하나를 바꿀 때 나머지가 조용히 따라
바뀐다 — 순서를 손대면 필터 후보가 달라지고, 어휘가 어긋나면 데이터가 **화면에서 없어진다**.
"어휘를 클라가 안다"는 가정 자체가 드리프트의 원천이었다.

**추가로 드러난 것**:
- **"보여준다"와 "도달할 수 있다"는 다르다.** 건수만 띄우고 필터 후보에서 빼면, 그 행들이
  표시 창(300) 밖일 때 **열람 자체가 불가능**하다(설계 원안이 이것을 "도달 불가와 다르다"고
  불렀고, 검토가 그 표현을 결함으로 잡았다).
- 필터 수용 어휘가 계약 enum뿐이라 **저장소에 실제로 있는 값으로 거르는 질의**가 422였다.
  답할 수 있는 질의를 오류라 부른 것이다.
- 422가 산문 `detail`만 주면 소비자는 어떤 값이 거절됐는지 알기 위해 **문장을 파싱**해야
  한다 — R5 위반을 소비자에게 강요하는 계약이다.
- 어휘 밖 상태 문자열이 저장돼 있으면 폴러가 `SessionState(...)`에서 예외를 내
  **그 레코드의 처리 전체가 매 틱 중단**됐다(라이브에서 발견).
- 그 값을 enum으로 강제해 보존하려 하면 `unknown`으로 덮어써 **알던 사실이 사라진다**.
  보존은 **원문 그대로** 쓸 때만 보존이다. 이벤트·알림 경로도 마찬가지여서, `from`을
  enum 기준으로 만들면 실제 전이가 `from: null`로 기록되고 오류 알림이 조용히 사라진다.

**규칙**:
1. **어휘의 소유자는 데이터를 가진 쪽**(서버)이다. 소비자는 받아 쓰고, 모르면
   **모른다고 표시**한다 — 하드코딩 목록으로 되돌아가지 않는다.
2. **아는 것 / 보여줄 순서 / 실제로 있는 것**은 세 개의 다른 사실이다. 한 값이 겸직하면
   분리하라. 순서 배열은 **순서만** 정한다 — 거기서 소속을 유도하면 서버가 수용한다고
   말한 적 없는 값이 후보가 된다.
3. **수용 어휘 = 계약 ∪ 관측.** 저장소에 있는 값으로 거르는 질의는 답할 수 있는 질의다.
   422는 계약에도 데이터에도 없는 값(오타)에만 쓴다. 빈 결과는 오류가 아니다.
4. 수용 판정과 응답은 **같은 스냅샷**에서 나와야 한다. 밖에서 판정하면 "수용했는데 분포엔
   없는 상태"가 생겨 봉투가 한 시점이라는 주장이 거짓이 된다.
5. **오류도 구조로 말한다**(`code`·`invalid_values`·`accepted`). 소비자는 그 필드로만
   분기하고, `code`가 없거나 모르는 값이면 **일반 실패로** 처리한다.
6. 거절된 사용자 입력은 **지우지 않는다.** 다음 질의에서만 빼고 "적용되지 않음"을 계속
   말한다. 그리고 그 거절은 **그때의 사실**이지 영구 판정이 아니다 — 서버가 다시 수용하면
   표시를 거둔다(단 어휘를 말하지 않는 응답에서는 거두지 않는다).
7. 재시도는 **조건이 반드시 줄어들 때만** 한다. 그렇지 않으면 무한 재귀로 단일 비행 latch가
   고착돼 화면이 무증상으로 멈춘다.
8. 어휘를 넓히면 그 값을 소비하는 **모든 경로**(판정·이벤트·알림·저장·화면)가 그것을
   견디는지 확인한다. 한 곳만 고치면 사실은 다른 곳에서 다시 사라진다.

**검증**: pytest 496 passed/1 skipped(+20 신규) · ruff · mypy strict 28 · node JS 계약 3종.
mutation 28건 실측(어휘 출처·수용 범위·스냅샷 경계·422 계약·폴백·UI 소비·재시도 유한성 —
각각 되돌리면 해당 게이트가 실패한다). 라이브(실 DB 사본 + 브라우저): 어휘 밖 `quarantined`·`retired`가
배지·건수로 보이고(`badge-unrecognized`), 필터 후보에 오르며, **보관 행에만 있는 `retired`로
실제 2행에 도달**했다. 오타 `typo-state`는 422 + 구조화 detail로 거절되고 선택은 남은 채
"서버가 모르는 필터 값(적용되지 않음)"으로 고지됐다.
독립 설계검토 **5R APPROVED** · 독립 구현리뷰 **5R APPROVED**(모두 교차 계열 Codex).
검토가 잡은 것: 도달 가능성 오주장 · 산문 파싱 강요 · 실측 서술과 재현 경로 불일치 ·
`observed_states` 유도 범위 · 스냅샷 경계 · 폴백 우선순위 · 검증 계획 내부 모순 ·
보관 상태 원문 유실 · 무한 재조회 · 거절 영구화 · 순서 배열의 소속 유도.
**자기 점검으로 잡은 것**: mutation 검증에서 `-k` 패턴이 **아무 테스트도 매칭하지 않아**
pytest exit 5를 "게이트 작동"으로 오독한 것(수집 건수 확인을 절차에 추가).
**NOT CLAIMED**: 브라우저 e2e 자동화(playwright 미설치) · 리터럴 스캔의 변수·조립 경유 ·
`apps` 파라미터 검증 비대칭 · 저장소 밖 API 소비자의 `detail` 타입 변경 호환.

## LESSON-006 — 어휘를 넓히면 기존 **이분법 분기**가 조용히 거짓이 된다 (2026-07-28)

**현상**: 실행 신호 축에 `unknown`·`not_applicable`을 추가하려는데, 그 값을 소비하는
분기가 `process_signal != "unavailable"`이었다. 어휘가 둘(`ok`/`unavailable`)일 때는 맞는
식이지만, 값이 넷이 되는 순간 **새 값 전부가 "가용"으로 통과**한다. 그 결과가
`liveness`로 흘러가 stale 구간을 `STALE`(=사실상 종료, 정리 대상)로 **확정**하는데,
같은 화면의 실행 열은 `확인 불가`라고 그린다 — 한 사실에 두 답.

**왜 놓치기 쉬운가**: 이 결함은 새 코드가 아니라 **기존 코드가 조용히 뜻을 바꾸는** 형태다.
테스트는 전부 초록이었다(옛 어휘만 검사했으므로). 설계 검토 3라운드에서야 잡혔고, 그전
개정은 이 파급을 "검토자에게 묻는 질문"으로만 남겼다 — **질문으로 남긴 파급은 해결된 것이
아니다**.

**추가로 드러난 것**:
- `count_scopes.matched == "not_applicable"`(조인 카운트를 세지 않음)을 "실행 신호를 줄 수
  없음"으로 읽을 뻔했다. codex는 그렇게 선언하면서 `osPid`로 `running_pid`를 **채운다**.
  가까이 있는 필드를 근거로 쓰기 전에 그 필드가 **무엇을 뜻하는지** 실측해야 한다.
- 기본값 `process_signal="ok"`는 아무도 선언하지 않아도 정상 관측으로 읽혔다.
  **기본값은 조용한 단언**이다.
- 내부 마커(`process-resume`)가 명령어 열에 원문으로 노출됐다. 실행된 적 없는 문자열을
  "실행 명령"이라 부른 것 — LESSON-003 계열(이름이 사실과 다름).

**규칙**:
1. enum을 넓힐 때는 **그 값을 읽는 모든 분기**를 함께 좁힌다. `!= 나쁜값`이 아니라
   `== 좋은값`으로 쓴다(fail-closed). 어휘 확장 PR은 소비자 grep이 필수다.
2. **구조적 가능성**(capability)과 **이번 관측 결과**(observation)는 다른 축이다.
   한 필드로 합치면 "줄 수 없다"와 "이번엔 못 얻었다"가 같아진다.
3. 기본값은 **모른다**여야 한다. 선언하지 않은 것을 정상으로 읽는 기본값은 미확인을
   사실로 승격한다.
4. 내부 마커는 **소유한 네임스페이스**에 두고, 표시 계층에는 원문이 아니라 **enum**을
   넘긴다. 표에 없는 마커는 명령으로 승격하지 않는다 — 마커가 늘 때 같은 결함이 반복된다.
5. 마커 원문은 텍스트뿐 아니라 **`title` 같은 부수 속성**에서도 새지 않아야 한다.
6. 판정 강화로 `UNKNOWN`이 늘어나는 것은 **대가가 아니라 사실의 회복**이다. 관측하지 못한
   세션을 "사실상 종료"로 확정하는 편이 더 비싸다.
7. **앱 단위 플래그로 레코드 단위 사실을 말하지 않는다.** `process_signal`은 앱 하나에
   값 하나라 "일부 대화의 신호만 못 봤다"를 표현할 수 없다 → 그런 사이클은 `ok`가 아니다.
   표현할 수 없는 사실을 유리한 쪽으로 반올림하면 그것이 왜곡이다.
8. **판별자는 판별에 실패해도 예외를 던지지 않는다.** `math.isfinite(10**400)`은
   `OverflowError`를 낸다 — 값 하나의 형식 오류가 수집 전체를 죽이면 멀쩡한 다른 대화의
   증거까지 미관측이 된다. 국소 오류를 전면 실패로 번지게 하지 않는다(LESSON-004 계열).
9. **모르는 값을 그럴듯한 기본값으로 심지 않는다.** 깨진 `updatedAtMs`를 0으로 채우면
   하류는 "1970-01-01에 마지막 활동"이라고 읽는다. 정렬 비교용 로컬 값과 **저장·표시되는
   사실**을 분리하라.
10. 타입 검사는 값 검사가 아니다. `NaN`·`Infinity`는 타입이 float이지만 시각이 아니고,
    JSON은 이 비표준 값을 기본 허용한다.

## LESSON-005 — "제외했다"는 고지는 실제로 제외됐을 때만 참이다 (2026-07-28)

**현상**: S3가 archived 세션을 수집에서 제외하고 `summary.excluded_archived=246`을
`summary.total=1073` **옆에** 실었다. 읽는 사람은 "246은 이 총계에서 빠졌다"고 결론낸다.
실제로는 `sessions`에 archived 컬럼 자체가 없었고, 제외는 **새 upsert만** 막았다. 이미
저장된 246행은 총계·상태 분포·"정리 대상" 수에 그대로 남아 있었다(claude 358 = 수집 112
+ "제외" 246, 정확히 일치).

**왜 침묵보다 나쁜가**: 침묵은 모름을 남기지만, 이 고지는 **일어나지 않은 위생 조치를
일어났다고 단언**한다. 사용자는 확인할 이유조차 갖지 못한다. LESSON-002가 "절단을 숨기지
말라"였다면, 이것은 그 반대편 실패다 — **하지 않은 일을 고지하기**.

**추가로 드러난 것**:
- 두 수가 **다른 축**이었다. `excluded_archived`는 "총계에서 빠진 행 수"가 아니라
  "최근 스캔이 본 archived 파일 수"다. 이름이 축을 감췄다.
- 보관 세션을 계속 재판정하니 이미 정리한 세션이 stale/error로 옮겨가 **"조치 필요"에
  섞였다** — S2가 656→3으로 줄인 결함의 재발 경로.
- 반대로 재판정을 멈추고 얼린 상태를 그대로 `by_state`에 두면, archive 직전 `running`이던
  세션이 **몇 달 뒤에도 현재 실행 중처럼** 집계된다.
- 서버 응답만 고쳐도 브라우저가 **낡은 JS를 캐시**하면 화면은 새 HTML + 옛 스토어가 되어
  `보관 undefined건`·`전체 300`(창 파생 KPI로 퇴행)이 뜬다. 어느 쪽 버전보다 나쁜 상태다.

**규칙**:
1. 고지 문구는 **실제로 일어난 연산**에서만 만든다. "제외했다"는 그 행이 집계에서 실제로
   빠졌을 때만 쓴다. 빠지지 않았으면 고지하지 말고 **빼거나**, 다른 이름을 붙인다.
2. **스캔이 본 수**와 **DB 행 수**는 다른 축이다. 절대 더하지 말고, 이름으로 구분하고,
   같은 시점인 것처럼 나란히 놓지 않는다.
3. 필터링을 수집에서 하면 **이미 저장된 과거 행은 영원히 분류되지 않는다**. 버리지 말고
   **플래그로 표시해 넘긴 뒤** 저장소·API가 범위를 정하게 한다. 버린 것은 분류할 수 없다.
4. 이름은 **DB predicate를 그대로** 말해야 한다. `active_total`은 "살아있음"을 함의하지만
   실제 조건은 "아직 archived로 관측되지 않음"이다 → `archive_not_observed_total`.
   이름과 사실의 괴리를 주석·문서로 덮으려는 충동이 곧 결함이다(LESSON-003 계열).
5. **행 수 사실**(`total`·`by_app`)과 **현재 상태 주장**(`by_state`)은 다른 종류다. 전자는
   보관을 포함해도 참이고, 후자는 모르는 것을 세면 거짓이 된다. 후자만 좁히고,
   좁힌 범위를 봉투가 **말한다**(`state_distribution_scope`).
6. 보관/삭제 예정 같은 **비-liveness 축**을 liveness 상태에 섞지 않는다. 관제 대상에서
   빼되(재판정·전이·SSE·알림·action/cleanup), **사실 분포에서는 빼지 않는다**.
7. 집계에서 뺀 것을 **도달 불가로 만들지 않는다**(LESSON-002 rule 8). `?archived=only`와
   화면의 "마지막으로 알던 상태"가 그 도달 경로다.
8. **API 기본값을 조용히 바꾸지 않는다.** 무엇을 목록에서 뺄지는 표시 정책이므로 소비자가
   명시 요청하게 한다. 기본 변경은 단계적 배포에서 조용한 제외를 만든다.
9. 무의미해진 설정은 **조용한 no-op으로 두지 않는다**. 경고 조건은 "무시되는 값"에 걸어야
   한다 — 기본값이 무시되는 경우가 흔하므로 값과 무관하게 알리는 편이 안전하다.
10. **의미가 바뀌는 수와 그 설명은 한 배포 단위**로 나간다. 정적 자원은 내용 해시로 URL을
    바꿔라. 봉투가 아무리 정직해도 브라우저가 옛 자원을 쓰면 계약은 지켜지지 않는다.

**검증**: pytest 397 passed/1 skipped · ruff · mypy strict 27 · node JS 계약 21.
mutation 5건 실측(분포 분리·폴러 보관 skip·기본 scope·중첩 옛 이름·해제 재판정 지연 —
각각 되돌리면 해당 게이트 실패). 라이브(실 DB 사본 + 실 수집 1사이클): `total 1073` 불변,
`archive_not_observed 827` + `archived 246` 등식 성립, `cleanup_required 1043→799`,
`archived_by_last_known_state {stale: 246}`. 브라우저 실측: 범위 고지·범위 라벨·보관 분포 표시.

## LESSON-004 — 수집이 버린 사실은 어떤 보고로도 복구되지 않는다 (2026-07-27)

**현상**: Slice 1·2로 보고가 정직해진 뒤에도 **실행 중인 claude 세션이 화면에서 죽은 것처럼**
보였다. `running_pid`가 `None`으로 하드코딩돼 있어 시간 폴백만 탔기 때문이다. 목록의
**246/358은 사용자가 이미 archive한 세션**이었고, 과거 `--fake` 데모의 6행이 실데이터
총계에 섞여 있었다.

**원인**: 수집 단계에서 사실을 버리거나(실행 신호 미수집), 사실이 아닌 것을 올렸다
(archived·합성 데이터). 보고 계층을 아무리 정직하게 만들어도 입력이 틀리면 복구되지 않는다.

**규칙**:

1. **실행 신호는 구조화된 CLI 토큰에서 얻는다.** 프로세스 커맨드라인의 `--resume=<uuid>`와
   세션 파일의 `cliSessionId`를 조인하면 실행 중 세션을 정확히 짚을 수 있다(실측 8/8).
   정규식으로 값만 긁지 말고 **argv로 분해한 뒤 exact token**으로 읽는다 — 따옴표·
   `=`/공백 두 형식·대소문자·malformed에서 조용히 깨진다.
2. **관측 실패를 빈 결과로 축약하지 않는다.** `status ∈ {OK, UNSUPPORTED, FAILED, TIMEOUT}`로
   구분하지 않으면 "세션 0개"와 "관측 실패"가 같은 값이 되어 관측이 거짓말한다.
3. **실패 시 이전 증거를 이월하지 않는다.** PID만 남기고 근거를 갱신하지 않으면, 그 PID가
   재사용됐을 때 `is_alive`가 참이 되어 **무관한 프로세스를 실행 증거로 오인**한다.
   증거는 "이번 스냅샷에서 재확인됨 + freshness 이내 + 살아 있음" 셋을 다 만족할 때만 쓴다.
4. **신호가 없는 동안 "종료"를 단언하지 않는다.** "확인 불가"라면서 동시에 STALE(사실상
   종료)로 분류하면 모순된 두 주장을 동시에 내놓는 것이고, 그 판정이 정리 대상 집계·필터로
   흘러간다. 활동 기반 서술(LIVE/IDLE/HOLDING)은 허용하되 종료 확정만 UNKNOWN으로 내린다.
5. **관측을 위해 민감정보를 저장하지 않는다.** 커맨드라인에는 토큰·프롬프트·경로가 들어 있다.
   OS 경계 밖으로 내보내는 것은 추출된 사실(pid·session_uuid·model)뿐이고, 원문은 매칭 후
   폐기한다(로그에도 남기지 않는다). 관측 개선이 정보 유출이 되면 안 된다.
6. **노이즈 제거도 절단이다.** archived 기본 제외처럼 정당한 필터도 **건수를 고지**하고
   설정으로 되찾을 수 있어야 한다(LESSON-002 rule 8과 같은 이유).
7. **버린 것은 센다.** 매칭 실패·모호(중복 uuid)·malformed는 조용히 넘기지 말고 사이클
   카운트로 표면화한다. 값이 없는 bare 플래그도 "의도는 있었으나 못 읽었다"이므로 센다.
8. **판정보다 사실을 먼저 남긴다.** "N틱 미출현 = 사라짐" 같은 판정은 수집 실패와 데이터
   부재를 구분하지 못한다. 이번엔 `collector_cycles`(status/collected/failed/
   excluded_archived/process_signal)만 남기고 판정은 유보했다.
   **`SUCCESS_COMPLETE, collected=0`과 `FAILED`는 절대 같은 값이 아니다.**
   수집기 예외도 사이클로 기록해야 한다 — 기록하지 않으면 이전 성공이 최신 건강도로 보여
   현재 실패가 은폐된다.
9. **비가역 작업에는 안전 계약을 붙인다.** 정리 명령은 미리보기가 기본, 정확 일치 범위,
   명시적 승인(`--yes`) 없이는 실행 금지, 삭제와 감사 기록은 **같은 트랜잭션**.
   감사 INSERT가 따로면 "지웠는데 기록이 없는" 상태가 생긴다.
10. **스키마에 컬럼을 더해도 기존 DB는 바뀌지 않는다**(`CREATE TABLE IF NOT EXISTS`).
   멱등 `ALTER TABLE` 마이그레이션이 없으면 **기존 설치에서만** INSERT가 깨진다.

**검증**: ACP pytest 370 passed(1 skipped), Ruff, mypy strict 27파일, node JS 계약 17 케이스.
라이브 실측 — claude 수집 358→112(archived 246 제외·고지), **실행 중 세션 7개 전부 RUNNING**
(pid·`process-resume` 마커, 이 세션 포함), `collector_health=success_complete`,
`app_signals` 노출, 기존 DB 마이그레이션 후 INSERT 성공, `purge --app fake` 미리보기가
6행을 표시하고 **삭제하지 않음**.

fake DB 격리 e2e), e2e(playwright 미설치).

## LESSON-003 — 판정 로직이 도는 것과 그 판정에 붙인 **이름이 맞는 것**은 다르다 (2026-07-27)

**현상**: Slice 1이 총계와 도달 가능성을 고친 뒤에도 대시보드는 "확인 필요 656건"을
보고했는데 그중 **95%(623건)가 stale** — 30일 전 죽은 세션이었다. HOLDING 배지는
52일 된 세션에 붙어 있었고, 중단된 턴(`turn_aborted` 실측 11건)은 어느 분기에도 닿지
않았으며, `[hold, ∞)` 전체가 UNKNOWN으로 뭉개져 "정보 없음"과 "오래 멈춤"이 같은 값이었다.

**원인**:

- `_ERROR_EVENTS = {"error", "task_aborted"}`가 **실데이터에 없는 어휘**였다(실측 0건).
  픽스처가 손으로 쓴 가짜 어휘를 담고 있어, 테스트가 초록인 채로 실어휘가 미검증이었다.
- in-turn 분기에 `stale_ttl` 단계가 없어 완료 이벤트 없이 닫힌 세션이 영구 HOLDING.
- 시간 폴백이 `hold` 초과를 전부 UNKNOWN으로 처리.
- `action` 축 하나에 "지금 손대야 함"과 "정리 대상"이 섞여 배지가 무의미해짐.

**규칙**:

1. **상태 이름은 실데이터 어휘로 검증한다.** 분기 상수와 실측 어휘의 관계를 계약으로
   고정하고(포함·배타·파티션), 실측에 없는 상수는 "레거시/방어"로 **명시 등재**해야
   통과시킨다. 조용한 dead branch를 금지한다. 실측 어휘는 추출기 산출 artifact가
   단일 출처이며, synthetic 픽스처는 계약 대상이 아니라고 라벨링한다.
2. **임계값의 열림/닫힘은 경로마다 달라지지 않는다.** 같은 hold/stale이 이벤트 종류에
   따라 다른 구간을 뜻하면 그 자체가 결함이다. 전 경로 `[hold, stale)`=HOLDING,
   `[stale, ∞)`=STALE로 통일하고 4점 경계를 테스트한다.
3. **UNKNOWN은 "판정 불가"에만 쓴다.** 오래 멈춘 것을 정보 없음과 같은 값으로 보고하면
   사용자가 원인을 추적할 수 없다.
4. **조치 축과 정리 축을 나눈다.** 한 축으로 뭉치면 다수를 차지하는 쪽이 배지를 무의미하게
   만든다. 단, **축을 뺀다고 조회·보존 대상에서 빼면 안 된다** — 그러면 그 세션들이 화면에서
   닿지 않고(LESSON-002 rule 8 회귀) `action=0`일 때 "정상"이라 단언하게 된다.
   빼는 것은 **알림 축에서만**이고, 화면은 두 축을 함께 표기한다.
5. **판정 규칙을 바꾸면 재분류 폭주를 함께 설계한다.** 규칙 변경은 오래된 행 수백 건을
   한 틱에 이동시키는데, 그건 사건이 아니라 재분류다. 알림에 freshness 게이트
   (`elapsed < stale_ttl`)를 걸되 **명시적 사건(오류 등)은 예외**로 둔다 —
   폭주를 막으려다 진짜 알림을 침묵시키면 반대 방향의 같은 결함이다.
6. **부분 표시의 예산에도 등급이 필요하다.** 조치 대상과 정리 대상을 같은 보존 예산에
   넣으면 다수인 정리 대상이 칸을 채워 정작 확인해야 할 것이 탈락한다. 탈락 고지도
   등급별로 세고, 원장은 등급 간 상호 배타를 유지한다.

**검증**: ACP pytest 333 passed(1 skipped), Ruff, mypy strict 27파일, node JS 계약 16 케이스.
라이브 재판정 실측 — `unknown` 364 → 1(판정 불가만), **`action_required` 656 → 3**,
`cleanup_required` 1045로 분리. **재판정 틱에서 423건이 stale로 이동했으나 알림은 1건**
(freshness 게이트 실증). 어휘 계약·경계·보존 우선순위는 각각 되돌려 실패를 실측했다.
독립 설계 검토(교차 계열 Codex) 4라운드 → PASS. 원안 D4(`action`에서 STALE 제거)는
설계 검토에서 **반려**되어 등급 분리로 대체됐다.

## LESSON-002 — 절단된 창에서 파생한 집계는 "요약"이 아니라 거짓 단언이다 (2026-07-27)

**현상**: DB에 세션 1009행이 있는데 대시보드는 "전체 300"이라 표시하고, 행동필요 634건을
0으로 보고해 **"정상"**이라 단언했다. codex 636행은 화면에 아예 없었고 모든 세션이 UNKNOWN으로
보였다. 사용자는 "관제가 안 된다"고 인식했지만, 수집기·liveness·저장은 전 구간 정상이었다.

**원인**: `list_sessions`가 `ORDER BY updated_at DESC LIMIT`으로 잘랐는데, `updated_at`은 세션
활동 시각이 아니라 **폴러가 행을 쓴 시각**이다. 폴러가 codex→claude→cursor 순으로 upsert하므로
정렬 상위는 항상 마지막 수집기의 행이 되고, 활성 세션은 구조적으로 창 밖으로 밀렸다.
그 위에서 UI가 잘린 배열의 길이·분포로 KPI를 계산해, 절단이 **침묵**에 그치지 않고
**능동적 오단언**으로 승격됐다.

**규칙**:

1. 총계·분포는 표시 창이 아니라 **전량 기준으로 서버가** 계산한다. 클라이언트가 받은
   배열 길이를 총계로 쓰지 않는다.
2. 절단은 반드시 경계를 넘어 표면화한다(`returned`/`total`/`truncated`). 리스트만 반환하는
   API는 호출자가 "받은 수 = 전체"로 오해하도록 구조적으로 유도한다.
3. 창과 집계는 **단일 read 스냅샷**에서 계산한다. 따로 조회하면 그 사이 쓰기가 끼어
   `sum(by_state) != total`처럼 내부 모순이 생긴다.
4. 정렬 키는 도메인 의미로 고른다. 쓰기 시각으로 자르는 것은 "수집 순서로 자르기"와 같다.
   동률은 유니크 키로 결정론적으로 깬다(페이지네이션 중복/누락 방지).
5. 집계가 낡았을 수 있으면 **"정상"이라 말하지 않는다**. 미확인과 이상 없음은 다르다.
   실시간 이벤트로 무효화된 순간 stale로 전환하고, 최신 세대의 성공 응답에서만 해제한다.
   무효화 시 in-flight 요청의 세대를 올려 폐기하지 않으면, 전이 **이전** 데이터가 도착해
   stale을 풀고 다시 거짓 안심을 만든다.
6. 클라이언트가 집계를 **가감 산술**로 유지하지 않는다. 중복·누락·재연결 이벤트에서 조용히
   드리프트한다. 권위 스냅샷 재조회(debounce)로 대체하면 드리프트할 산술 자체가 사라진다.
7. **테스트가 갭을 가리지 않게 한다**: 이 결함은 e2e 테스트가 `?limit=300`으로 우회하고
   KPI를 "잘린 창 카운트와 같은지"로 검사해 **버그를 정상 동작으로 고정**하고 있었다.
   회귀 테스트는 "구현을 되돌리면 실패하는가"로 판별력을 실증한다.
8. **정직한 총계로는 부족하다 — 그 총계가 가리키는 것에 "도달 가능"해야 한다.**
   정렬키 `last_activity`는 `stale`/`holding`과 **반상관**이라, 창을 활동순으로만 자르면
   KPI가 세는 조치 대상이 구조적으로 창 밖에 남는다(실측: DB의 유일한 `error` 1건이
   창 밖 → 필터를 켜면 "세션 없음"). 결함이 "0으로 보고"에서 "정확히 652로 보고하되
   67%는 열람 불가"로 옮겨갔을 뿐이다. **필터는 서버에서 전량에 걸고**, 필터 옵션 목록도
   창이 아니라 전량 집계에서 만든다. 조건 일치 수(`matched`)와 전량(`total`)을 분리해
   무엇이 잘렸는지 고지한다.
9. **조용한 정지는 조용한 거짓만큼 나쁘다.** 동시 요청을 세대 번호로만 막으면 요청이
   완료보다 빨리 발생하는 구간에서 **모든 응답이 폐기돼 화면이 굳는다**(실측: 50ms 내
   동일 요청 6건). 단일 비행으로 묶되, **타임아웃 없는 fetch는 latch를 영구 고착**시켜
   무증상 정지를 만든다 — 중단 신호를 반드시 건다. 이런 실패 모드는 "거짓 안심 제거"라는
   목적과 정면으로 충돌하므로, 수정이 새로 만든 실패 모드가 없는지 함께 본다.
10. **부분 표시에는 종료 계약과 고지가 함께 붙는다.** 창 밖 전이를 클라가 붙잡아 두는
   보상 로직에도 상한·해제 조건·탈락 고지가 없으면, 서버 절단을 고친 자리에서 클라 절단이
   새로 생긴다. 고지 문구는 출처를 뭉뚱그리지 않는다(서버 창 N건 + 보존 M건을 "상위 N+M건"이라
   부르면 그 자체가 거짓).

**검증**: targeted 19 + JS 계약 14종, ACP full 314 passed(1 skipped), Ruff, mypy strict 27파일,
라이브 실측(returned 300/matched 1029/total 1029, `?states=error`→1건 도달, action 필터
`matched == summary.action_required`, `?apps=cursor`→11건, `limit=-1`·미지 state→422).
교차 계열(Codex) 독립 리뷰 R1~R9 + 독립 적대적 리뷰 2회: CHANGES_REQUESTED 반복 →
rule 8·9는 **적대적 리뷰가 6라운드 교차 리뷰를 통과한 코드에서** 잡아냈다.
**NOT CLAIMED**: e2e(playwright 미설치 + `-m 'not e2e'`로 이 환경 실행 불가), 브라우저 UI
최종 렌더 재확인(pane 무응답).

## LESSON-001 — 검증된 모델 인스턴스도 권위 경계에서 다시 검증한다 (2026-07-22)

**현상**: Pydantic `model_construct()`로 만든 `round=True`/`1.0` binding이 정상 `round=1`과 같다고 비교되어,
issue 실패 뒤 DB side effect가 남거나 consume이 실제 승인으로 끝날 수 있었다. 또한 `raise ... from None`은 표준
traceback을 숨겨도 suppressed `__context__`에는 raw nonce/signature가 남았다.

**원인**: 타입 힌트와 이미 생성된 모델 인스턴스를 권위 입력으로 신뢰했고, Python의 `bool == 1 == 1.0` 동등성과
예외 객체의 cause/context 보존을 경계 계약에 포함하지 않았다.

**규칙**:

1. 승인·권한·상태 전이 입력은 모델 인스턴스라도 field-by-field plain data로 추출해 strict schema로 재검증한 뒤
   side effect와 equality에 사용한다.
2. fail-closed는 반환값뿐 아니라 side effect 순서까지 포함한다. 검증 실패 전에는 nonce 생성·DB insert/update·audit을
   수행하지 않는다.
3. secret/nonce/signature redaction은 `str`/`repr`/`__cause__`/`__context__`/formatted traceback/DB를 함께 검사한다.
   raw 입력 예외는 helper 내부에서 소비하고 active exception context 밖에서 sanitized domain error를 만든다.
4. secret resolver는 arbitrary callable보다 explicit immutable allowlist를 우선하며 default/file/self-generated fallback을
   구조적으로 제공하지 않는다.

**검증**: T10-B3a corrective R2에서 targeted 44, ACP full 294 passed(1 skipped), Ruff, mypy strict, 독립
same-lineage R3 재현 프로브 PASS. Claude cross-lineage output PASS는 429로 NOT CLAIMED.
